## 작업 1 — 문헌 반지름비를 아카이브에서 직접 받아 쓰기 (가장 중요)

### 무엇이 문제인가

식현상 모듈의 「문헌값 비교」 화면은 학습자 측정 Rp/R*를 아카이브 값과 나란히 보여준다. 그런데 백엔드가 아카이브에서 **식 깊이(`pl_trandep`)만** 받아 오고, 프런트가 그것을 √해서 반지름비를 만든다.

문제는 아카이브의 대표값 테이블(`pscomppars`)이 깊이와 반지름비를 **서로 다른 출처에서 조합**한다는 것이다. WASP-6 b가 그렇다.

| 대상 | `pl_trandep` → √(깊이) | 같은 행의 `pl_ratror` | 차이 |
|---|---|---|---|
| **WASP-6 b** | 2.40817811% → **0.1552** | **0.1446 ± 0.0009** | 7.3% |
| WASP-121 b | 1.5018% → 0.1226 | 0.122551 ± 0.000063 | 거의 같음 |
| WASP-151 b | 1.0664% → 0.1033 | 0.1011 ± 0.0005 | 2% |

**중요 — 기준값의 출처도 함께 보여야 한다.** 아카이브의 대표값은 여러 관측을 종합한 것일 수 있다. WASP-6 b의 `pl_ratror` 0.1446은 Kokori et al.(2023, ExoClock III)이 지상 관측망·문헌·우주망원경(Kepler/K2/TESS) 약 18,000개 관측점을 종합해 낸 값이고, 같은 행성의 다른 값으로 Tregloan-Reed et al.(2015) 0.1463, Patel & Espinoza(2022) 0.1453도 아카이브에 있다.

학습자가 쓰는 자료는 TESS 컷아웃 하나인데 기준값은 여러 관측의 종합이므로, **두 값이 같은 조건에서 나온 것이 아니라는 사실을 화면이 밝혀야 한다.** 값을 감추거나 고르는 것이 아니라 출처를 드러내는 것이 이 수정의 목적이다.

WASP-6 b는 시연의 기본 예제 대상이다. 2026-07-24 조사에서 학습자 14명의 측정 중앙값은 **0.1457**이었는데, 화면은 0.1552를 문헌값으로 보여줘 **6.1% 얕게 쟀다**고 읽혔다. 아카이브의 반지름비 0.1446과 비교하면 **+0.8%로 사실상 일치**한다. 즉 측광·적합은 잘 작동하는데 비교 기준이 어긋나 있었다.

(참고: 학습자 측정이 문헌보다 얕게 나오는 계통 요인 — 이웃별 빛 혼입 — 은 별개로 존재하고 논문 4.4.4에 정량 분해되어 있다. 이 작업은 그 요인을 없애는 게 아니라, **기준값 자체의 불일치**만 제거한다.)

### 고칠 곳

**① `backend/adapters/transit_archive.py`**

- TAP 질의(약 274행부터, `select top {limit} …`)의 컬럼 목록에 `pl_ratror, pl_ratrorerr1, pl_refname`을 추가한다. 같은 파일의 다른 질의(약 339행)에도 같은 컬럼이 필요하다.
- `_build_live_target()`(약 225행~)이 만드는 dict에 `radius_ratio`, `radius_ratio_err`, `radius_ratio_ref`를 추가한다. 값이 없으면 `None`.
- `pl_refname`은 HTML 앵커 태그가 섞인 문자열로 온다(예: `<a refstr=KOKORI_ET_AL__2023 href=... >Kokori et al. 2023</a>`). 태그를 벗겨 표시용 문자열(`Kokori et al. 2023`)만 남기는 함수를 두고, 실패하면 `None`으로 둔다.
- `pl_ratror`는 null일 수 있다. `where` 절에 `pl_ratror is not null`을 **넣지 말 것** — 넣으면 대상 목록이 줄어든다. 값이 없는 대상은 지금처럼 깊이에서 환산하면 된다.
- `_passes_catalog_filters()`의 필터 조건은 건드리지 않는다.

**② `backend/schemas/target.py`**

`Target` 모델에 `radius_ratio: float | None = None`, `radius_ratio_err: float | None = None`, `radius_ratio_ref: str | None = None` 추가.

**③ `frontend/src/components/inquiry/TransitComparison.tsx`** (약 262~268행)

```ts
const archiveRpRs =
  target?.transit_depth_pct != null && target.transit_depth_pct > 0
    ? Math.sqrt(target.transit_depth_pct / 100)
    : null;
```

를, `target.radius_ratio`가 있으면 그것을 쓰고 없을 때만 √(깊이)로 되짚도록 바꾼다. 어느 쪽을 썼는지 화면이 구분할 수 있게 상태를 함께 둔다(예: `refSource: 'archive' | 'derived'`).

**④ 같은 파일 약 436행의 안내 문구**

현재는 항상 「여기 문헌값은 … 식 깊이에서 √(식 깊이)로 되짚어 계산한 것입니다 …」라고 말한다. 아카이브 반지름비를 쓰는 경우에는 이 문장이 거짓이 되므로 분기한다.

- 아카이브 값을 쓸 때: 「이 문헌값은 NASA Exoplanet Archive가 수록한 반지름비입니다(출처: {radius_ratio_ref}). 여러 관측을 종합한 값일 수 있어, 지금 내가 분석한 TESS 자료 하나와 같은 조건에서 나온 값이 아닙니다.」 불확도가 있으면 `0.1446 ± 0.0009`처럼 함께 표시한다.
- 깊이에서 환산할 때: 지금 문장 유지.
- **출처 문자열은 값 옆에 항상 보이게 둔다**(툴팁 안에만 숨기지 말 것). 값과 출처가 함께 보여야 학습자가 무엇과 비교하는지 안다.

**⑤ 다른 화면에도 같은 계산이 있는지 확인**

`grep -rn "transit_depth_pct" frontend/src`로 훑어, 반지름비를 √(깊이)로 만드는 곳이 더 있으면 같이 고친다. 탐구 블럭 6단계의 오른쪽 레일(`TransitStep6Rail`)과 결과 요약(`TransitResultSummary`)을 특히 볼 것.

**⑥ 번들·캐시 대상**

`_build_live_target` 외에 미리 저장해 둔 대상 정의가 있으면 거기에도 필드를 넣거나, 없으면 `None`으로 두어 ⑤의 폴백이 동작하는지 확인한다.

3. `cd frontend && npm run build` 후 `http://localhost:5895`에서 식현상 → WASP-6 b → 5단계까지 실제로 수행해 **화면의 문헌값이 0.1446 ± 0.0009로 바뀌고, 출처(Kokori et al. 2023)가 값 옆에 보이며, 안내 문구가 「여러 관측을 종합한 값」임을 말하는지** 눈으로 확인한다. 스크린샷을 남긴다.
4. `npx tsc --noEmit` 통과, `npm run test:unit` 실행(기존 실패 1건 `validationStats.test.ts`는 무관).
