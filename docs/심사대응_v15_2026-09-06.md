### B-2. 부호화의 AI 관여 — 심사 지적의 사실관계가 달랐다

심사(편집장·방법론)는 "최초 범주 판정은 AI가 내렸고 연구자가 보정했다"고 보았고, 나도 그렇게 보고했다.

소유자 교정: **"연구자 1인 맞잖아 내가 하나하나 다 한건데, 웹 개발만 AI 바이브코딩으로 한 거고."**

확인해 보니 소유자 말이 맞다. `연구자_응답별검토_2026-09-05.md`에 44개 응답을 하나씩 읽고 판단한 원문이 있고, 중간에 "아 잠시만 기존 서비스에 대한 교사들의 평가구나?"처럼 **응답 원문을 보고 스스로 고친 흔적**이 있다. AI 판정을 따라간 것이 아니다.

→ 3.6의 「연구자 1인이 수행」 **유지**. 이미 있는 생성형 AI 활용 고지에 정리 보조 사용이 적혀 있어 추가 서술 없음.

### B-3. WASP-6 b 기준값 — 소유자 질문에서 시작해 원고 오류를 잡았다

소유자 질문: **"내가 실제로 WASP-6b 할 때는 문헌값이랑 한 6% 정도 차이 났는데? 뭐지"**

추적 결과:

1. 라이브 API 조회 → 앱이 쓰는 `transit_depth_pct` = **2.40817811%**, 화면 문헌값은 √로 환산한 **0.1552**
2. 원고는 「기준값 약 0.146, 차이 0.0003」이라고 적고 있었다 → **학습자가 화면에서 본 비교와 다른 비교**
3. 소유자 재질문: "2.4%가 실제로 있는 아카이브 값이고 잘못된 건 아닌데 그냥 오차가 있는 값이지?" → 불확도 조회 결과 ±0.010으로 **세 값 중 가장 작다.** "잘못된 값"이라 한 내 표현이 과했다
4. 소유자 결론: **"앱 내에서 차이를 보는 게 변인통제로써는 맞고, 지상관측은 데이터부터 다르니 비교가 안 되지"**

→ 이 방침대로 4.5를 앱 내부 비교만 남기고 단순화했다. 외부 논문값(Gillon 2009·Stassun 2017) 서술과 아카이브 내부 불일치 논의는 전부 제거하고, 참고문헌에서도 뺐다.

**최종 수치**(원자료 재계산):

| | 값 |
|---|---|
| 화면 문헌값 | 0.1552 (√2.408%) |
| 측정 중앙값(14건) | **0.1457** → −6.1% |
| 정상 적합 12건 | 중앙값 0.1457 · 범위 0.1410~0.1536 · SD 0.0033 |
| 깊이 중앙값 | 2.123% (문헌 2.408%의 **0.881배**) |

이 과정에서 **내가 원고에 0.1453을 잘못 넣은 것도 잡았다**(Stassun의 반지름비와 혼동). 0.1457이 맞고, 원래 원고 값이 옳았다.

원인: 플랫폼 측광이 이웃별 혼입을 보정하지 않는다. 컷아웃 FITS에 `CROWDSAP`이 아예 없음을 직접 확인했다(네 섹터 전부 `None`). WASP-121 b의 −12%와 **같은 요인**이므로 4.4.4와 4.5가 하나의 이야기가 된다.

### B-4. 연구윤리 심의(IRB)

관점 심사가 게재 전 필수로 지정했다. 소유자: "엥? 난 들어본 적도 없는데, ERP 연구보고서 작년에 낼 때도 안 했는데."

→ ERP 추진계획 hwp를 열어 확인. **IRB·생명윤리 심의 요구 조항 없음**("심의"는 연구비 심사위원회, "개인정보"는 자문료 지급용 동의서).

→ 3.6에 사실만 적었다: 익명 수집, 개인식별정보 미수집, 첫 문항 동의 확인, 소속 기관 연구활동 지원 프로그램 절차에 따라 수행. **학회 투고 규정 확인은 남아 있다.**
